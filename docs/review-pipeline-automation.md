# 리뷰 파이프라인 자동화

## 부모-자식 일괄 검수

`Review > 부모-자식 일괄 검수`에서 구조적으로 연관된 캐릭터를 부모 카드와 자식 후보 카드로 묶어 검토한다. 기존에 연결된 자식은 우선 표시되며, 이미지·rating·review 상태와 관계없이 후보에 포함될 수 있다.

- 방향키: 카드 이동
- `A`: 현재 자식의 연결 선택/해제
- `Space`: 생성 이미지와 Danbooru 참고 이미지 비교
- `Enter`: 선택한 그룹을 한 트랜잭션으로 적용

적용 시 선택된 자식의 부모 관계를 갱신하고, 옵션에 따라 부모의 비어 있지 않은 공통 외형 필드와 rating을 자식의 빈 필드에만 채운다. 부모와 자식 값이 다르면 자동으로 덮어쓰지 않고 충돌로 표시한다. 기존에 다른 부모가 있거나 자식 계층을 가진 후보, 순환 관계, 현재 그룹에 속하지 않은 ID는 거부한다. 이미지가 없는 자식은 관계와 메타데이터를 적용할 수 있지만 `inherited_review_pending_image` 상태로 남길 수 있다.

후보 제외는 부모-후보 쌍으로 저장되며 이후 목록에서 유지된다. 이미 연결된 자식을 제외하면 해당 부모 연결을 해제한다.

## Danbooru 비교 미리보기

V2 리뷰, 부모-자식 검수, 비인간 분류에서 카드에 포커스를 두고 `Space`를 누르면 생성 이미지를 즉시 연다. Danbooru 참고 이미지 메타데이터는 dialog가 열린 뒤 현재 캐릭터에 대해서만 최대 3건 조회한다.

- `Escape`: 닫기
- `Tab` / `Shift+Tab`: dialog 내부 포커스 이동
- 기존 화면 맞춤 버튼: 생성 이미지 표시 크기 전환

요청은 dialog 종료 또는 대상 변경 시 취소하며, 오래된 응답은 새 캐릭터에 표시하지 않는다. API는 preview/sample/file URL과 post 메타데이터만 반환한다. Danbooru 이미지 binary를 앱 서버나 로컬 디스크에 저장하지 않으며, 메타데이터 캐시는 최대 100개 항목·30분 TTL로 제한된다. 조회 실패는 생성 이미지 표시와 리뷰 진행을 막지 않는다.

## 비인간형 후보 분류

`Review > 비인간 분류`는 저장된 시리즈, 캐릭터/외형 태그, 이미지 태거 결과와 gender 신호를 조합해 후보와 점수·근거를 제시한다. Pokémon/Digimon 같은 시리즈명만으로 자동 확정하지 않으며, 최종 판정은 항상 사용자가 저장한다.

- `-`: rating `-1`(비인간·카탈로그 대상 아님) 선택
- `0`: rating `0`(원하는 형태로 생성 불가) 선택
- `3`: rating `3`(사람형 여성 캐릭터로 생성 가능) 선택
- `U`: 일반 리뷰로 이동 선택
- `Enter`: 선택한 판정 저장
- 방향키: 카드 이동
- `Space`: 생성 이미지와 Danbooru 참고 이미지 비교

사용자 판정, 판정 시각, 후보 점수·근거와 분류기 버전을 저장한다. 규칙을 다시 계산해도 기존 사용자 판정을 덮어쓰지 않는다. 완료 리뷰나 기존 rating/판정을 바꾸려면 UI 확인 후 명시적인 `reopen_completed` 및 `overwrite_existing` 옵션을 전송해야 한다. 일반 리뷰로 보낸 항목은 rating을 임의 변경하지 않고 `pending` 상태로 돌린다.

## 데이터와 성능

- 부모-자식 일괄 적용은 단일 DB 트랜잭션이며 실패 시 전체 rollback한다.
- 기존 완료 rating, 대표 이미지, 프롬프트, 수동 외형 태그, 생성 횟수와 이미지 파일은 명시적인 사용자 동작 없이 변경하지 않는다.
- 부모 그룹과 비인간 후보 목록은 DB pagination과 eager/batch loading을 사용한다.
- 부모 그룹 후보는 SQL `EXISTS`로 먼저 제한해 전체 캐릭터를 Python 메모리에 올리지 않는다.
- 개별 카드 저장 실패는 해당 화면에 표시되며 전체 목록 탐색은 계속할 수 있다.
