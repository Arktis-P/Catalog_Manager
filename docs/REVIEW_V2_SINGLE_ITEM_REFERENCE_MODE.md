# Review V2 단일 항목 레퍼런스 모드 구현 지시서

## 1. 목적

Review V2의 기존 5개 카드 검토 화면과 기능을 그대로 유지하면서, 모르는 캐릭터를 빠르게 식별할 수 있는 **단일 항목 레퍼런스 모드**를 추가한다.

이 기능의 핵심 목적은 `w` 키로 Danbooru 위키를 열고 외부 브라우저에서 캐릭터를 확인한 뒤 앱으로 돌아오는 반복 작업을 줄이는 것이다.

기존 Review V2를 대체하거나 수정하는 기능이 아니다. 같은 검토 데이터와 키 바인딩을 공유하는 보조 화면으로 구현한다.

---

## 2. 변경하지 말아야 할 항목

다음 기능은 기존 동작을 유지한다.

- Review V2의 한 화면 5개 카드 표시
- 카드 내 생성 이미지, 캐릭터 정보, 태그 편집, 기본 프롬프트, 기능 버튼
- `Enter`를 통한 현재 항목 저장
- `Ctrl+Enter`를 통한 현재 페이지 일괄 저장
- 기존 평점, 성별, 재생성, 이미지 선택 관련 단축키
- `w` 키의 Danbooru 위키 페이지 열기
- 기존 필터, 정렬, 페이지네이션, pending 판정 방식
- 재생성 중인 이미지의 회색 오버레이 표시

새 모드에서 기존 컴포넌트와 상태를 최대한 재사용하되, 기존 화면의 동작을 변경하지 않는다.

---

## 3. 진입 및 종료 방식

### 3.1 진입

Review V2 화면에 **단일 항목 보기** 전환 버튼을 추가한다.

- 현재 선택된 카드가 있으면 해당 항목으로 진입한다.
- 선택된 카드가 없으면 현재 페이지의 첫 번째 pending 항목으로 진입한다.
- pending 항목이 없으면 진입하지 않고 안내 메시지를 표시한다.

### 3.2 화면 형태

별도 라우트나 페이지로 이동하지 않고, Review V2 위에 표시되는 **전체 화면 오버레이 또는 대형 모달**로 구현한다.

목적:

- 기존 Review V2의 필터, 페이지, 선택 상태 유지
- 기존 키 바인딩 재사용
- 닫은 뒤 원래 위치로 즉시 복귀

### 3.3 종료

- 닫기 버튼 또는 `Esc`로 종료한다.
- 종료 시 현재 Review V2의 페이지와 선택 위치를 유지한다.
- 단일 항목 모드 전용 메모리 캐시는 정리한다.

## 4. 화면 구성

전체 화면을 좌우 `[ A | B ]` 구조로 나눈다.

```text
┌──────────────────────────────┬─────────────────────────────┐
│                              │ B상: 정보 및 조작           │
│                              │                             │
│ A: Generated Image           │ 캐릭터 정보                 │
│                              │ 태그 편집                   │
│ 이미지 비율을 유지하며       │ 기본 프롬프트               │
│ 영역에 맞게 최대 표시        │ 기존 기능 버튼              │
│                              │                             │
│                              ├─────────────────────────────┤
│                              │ B하: Reference Images       │
│                              │ □ □ □ □ □                   │
└──────────────────────────────┴─────────────────────────────┘
```

### 4.1 A 영역: 생성 이미지

- 현재 항목의 generated image를 표시한다.
- 원본 비율을 유지한다.
- 영역 안에서 가능한 한 크게 표시하되 잘리지 않도록 한다.
- 기존 이미지 선택, 확대, 재생성 상태 표시 규칙을 유지한다.
- 재생성 중이면 기존과 같은 회색 오버레이와 재생성 상태 문구를 표시한다.

### 4.2 B상 영역: 기존 카드 정보

기존 Review V2 카드에 있던 내용을 동일하게 제공한다.

- 캐릭터 이름 및 기본 정보
- 시리즈 정보
- 수정 가능한 태그 정보
- 입력된 기본 프롬프트
- 평점 및 상태
- 기존 기능 버튼
- 위키 및 포스트 열기 기능

기존 카드 컴포넌트를 그대로 확대 배치하거나, 동일 상태와 이벤트 핸들러를 공유하는 전용 레이아웃 컴포넌트를 만든다.

### 4.3 B하 영역: 레퍼런스 이미지

- 정사각형 썸네일 플레이스홀더 5개를 한 줄로 표시한다.
- B하 영역의 높이는 정사각형 썸네일 5개와 최소한의 여백 및 라벨이 들어가는 정도로 제한한다.
- 항상 5개 슬롯을 유지한다.
- 이미지가 부족한 슬롯은 빈 상태를 명확히 표시한다.
- 로딩 중에는 각 슬롯에 로딩 플레이스홀더를 표시한다.
- 레퍼런스 로딩 실패가 전체 검토 화면 사용을 막아서는 안 된다.

## 5. 레퍼런스 이미지 선정 규칙

레퍼런스 이미지는 캐릭터에 연결된 기존 Danbooru 태그를 사용한다. 별도의 캐릭터명 추정이나 태그 검색 보정 기능은 이번 범위에 포함하지 않는다.

### 5.1 1순위: Wiki Sample

해당 캐릭터의 Danbooru 위키 페이지에 예시로 삽입된 이미지 또는 포스트를 우선 사용한다.

- 최대 5장까지 가져온다.
- 위키 본문 전체를 저장하거나 표시하지 않는다.
- 필요한 것은 예시 이미지에 연결된 포스트 ID 또는 이미지 URL뿐이다.
- 각 썸네일 위쪽 또는 아래쪽에 `WIKI` 또는 `Wiki Sample` 라벨을 표시한다.
- 같은 포스트가 중복으로 포함되지 않도록 한다.

### 5.2 2순위: Favorite 상위 포스트

Wiki Sample이 5장보다 적을 때 남은 슬롯을 favorite 수가 높은 포스트로 채운다.

예시:

- Wiki Sample 5장: Wiki Sample 5장만 표시
- Wiki Sample 3장: Wiki Sample 3장 + favorite 상위 포스트 2장
- Wiki Sample 1장: Wiki Sample 1장 + favorite 상위 포스트 4장
- Wiki Sample 0장: favorite 상위 포스트 5장

조건:

- 현재 캐릭터 태그가 포함된 포스트
- Wiki Sample과 중복된 포스트 제외
- 동일 포스트 및 동일 이미지 중복 제외
- favorite 내림차순 우선
- 필요한 경우 score 또는 post ID를 보조 정렬 기준으로 사용

### 5.3 범위 제외

다음 기능은 구현하지 않는다.

- 레퍼런스 이미지 태그 정보 표시
- Wiki 설명문 또는 전체 Wiki 본문 표시
- generated image와 reference image의 AI 자동 비교
- 캐릭터 일치율 자동 판정
- 별도의 태그명 검색 또는 유사 태그 추정

## 6. 레퍼런스 이미지 상호작용

썸네일을 선택했을 때 다음 중 하나를 구현한다.

### 권장 기본 동작

- 클릭 시 앱 내부에서 더 큰 이미지 미리보기를 표시한다.
- 미리보기에는 원본 Danbooru 포스트를 여는 버튼을 제공한다.

### 허용 가능한 단순 구현

- 썸네일 클릭 시 해당 이미지의 Danbooru 포스트 페이지를 외부 브라우저에서 연다.

가능하면 첫 번째 방식을 우선하되, 구현 복잡도가 커지면 두 번째 방식으로 시작해도 된다.

`w` 키의 기존 Wiki 열기 기능은 반드시 유지한다.

## 7. 항목 이동 및 페이지 연동

단일 항목 모드는 현재 Review V2의 **pending 항목 순서**를 기준으로 이동한다.

### 7.1 방향키 이동

- 다음 방향키: 다음 pending 항목으로 이동
- 이전 방향키: 이전 pending 항목으로 이동
- 현재 Review V2 페이지의 마지막 pending 항목에서 다음으로 이동하면 다음 페이지를 자동 로드하고 첫 pending 항목을 표시
- 현재 페이지의 첫 pending 항목에서 이전으로 이동하면 이전 페이지를 자동 로드하고 마지막 pending 항목을 표시
- 필터, 정렬, 시리즈 조건은 현재 Review V2 상태를 그대로 따른다.

기존 키 바인딩과 충돌하지 않도록 현재 Review V2에서 항목 이동에 사용하는 방향키 규칙을 그대로 재사용한다.

### 7.2 Enter 저장

- 현재 항목만 저장한다.
- 저장으로 pending 대상에서 제외되면 다음 pending 항목으로 이동한다.
- 다음 항목이 없으면 다음 페이지를 탐색한다.
- 전체 pending 항목이 끝나면 완료 상태를 표시한다.

### 7.3 Ctrl+Enter 일괄 저장

- 기존 Review V2의 현재 페이지 일괄 저장 로직을 그대로 호출한다.
- 저장 완료 후 갱신된 현재 페이지의 가장 앞 pending 항목을 표시한다.
- 현재 페이지에 pending 항목이 없으면 다음 pending 페이지의 첫 항목으로 이동한다.
- 일괄 저장 결과로 현재 캐시 범위가 무효화되면 캐시를 갱신한다.

### 7.4 재생성 항목

- 재생성 중인 항목도 이동 순서에서는 건너뛰지 않는다.
- 해당 항목에 도달하면 generated image 영역에 회색 오버레이를 표시한다.
- 기존 재생성 완료 이벤트를 받으면 화면을 자동 갱신한다.

## 8. 레퍼런스 프리로드 및 캐시

### 8.1 로딩 시작 시점

단일 항목 모드에 진입한 시점부터 레퍼런스 이미지 로딩을 시작한다.

### 8.2 프리로드 범위

현재 pending 항목을 기준으로 다음 범위를 준비한다.

- 이전 pending 항목 5개
- 현재 pending 항목 1개
- 이후 pending 항목 20개

현재 항목의 요청을 가장 높은 우선순위로 처리하고, 이후 항목, 이전 항목 순으로 백그라운드 로딩한다.

페이지 경계를 넘어가더라도 현재 필터와 정렬 기준의 pending 순서를 사용한다.

### 8.3 캐시 대상

캐시에는 최소한 다음 정보만 저장한다.

- 캐릭터 ID 또는 태그 ID
- reference post ID
- 썸네일 URL
- 원본 또는 큰 미리보기 URL
- Danbooru post URL
- Wiki Sample 여부
- 로딩 상태 및 실패 상태

레퍼런스 이미지의 실제 원본 파일을 영구 저장하지 않는다. 세션 내 메모리 또는 임시 디스크 캐시를 사용한다.

### 8.4 캐시 무효화

다음 상황에서 현재 대상과 맞지 않는 캐시를 제거하거나 새 범위로 교체한다.

- 단일 항목 모드 종료
- 필터 변경
- 정렬 변경
- 시리즈 변경
- 페이지 또는 pending 목록이 대규모로 변경됨
- `Ctrl+Enter` 일괄 저장으로 여러 pending 항목이 제거됨

개별 `Enter` 저장 때마다 전체 캐시를 삭제하지 않는다. 현재 위치를 기준으로 앞 5개, 뒤 20개 범위를 다시 계산하여 범위 밖 항목만 제거한다.

### 8.5 요청 제어

- 동시에 과도한 Danbooru 요청을 보내지 않도록 동시 요청 수를 제한한다.
- 빠르게 항목을 이동할 때 오래된 요청 결과가 현재 항목 UI를 덮어쓰지 않도록 요청 키 또는 취소 처리를 사용한다.
- 실패 요청은 짧은 지수 백오프 또는 제한된 횟수로 재시도한다.
- 404, 이미지 없음, Wiki Sample 없음은 오류가 아니라 정상적인 빈 결과로 처리한다.

## 9. 백엔드 권장 구조

프론트엔드에서 Danbooru를 직접 호출하기보다 기존 FastAPI 백엔드를 통해 조회한다.

권장 API 예시:

```text
GET /api/review/reference-images/{character_id}
```

응답 예시:

```json
{
  "character_id": 123,
  "tag": "character_tag",
  "items": [
    {
      "post_id": 10001,
      "thumbnail_url": "...",
      "preview_url": "...",
      "post_url": "...",
      "source": "wiki_sample"
    },
    {
      "post_id": 10002,
      "thumbnail_url": "...",
      "preview_url": "...",
      "post_url": "...",
      "source": "favorite"
    }
  ]
}
```

백엔드 서비스는 다음 순서로 처리한다.

1. 캐릭터에 연결된 Danbooru 태그 확인
2. Wiki Sample 포스트 ID 또는 이미지 링크 조회
3. 최대 5개까지 중복 제거
4. 부족한 수만큼 favorite 상위 포스트 조회
5. 정확히 최대 5개 결과 반환

Danbooru 페이지 자체를 앱 안에 임베드하지 않는다. API 또는 서버 측 HTML 파싱으로 필요한 포스트와 이미지 정보만 추출한다.

Wiki 구조 변경에 대비하여 Wiki Sample 추출 로직과 favorite fallback 로직을 분리한다.

---

## 10. 프론트엔드 권장 상태 구조

단일 항목 모드 전용 상태는 기존 Review V2 상태에서 파생한다.

권장 상태:

```text
singleModeOpen
activeCharacterId
activePendingIndex
referenceCache
referenceLoadingState
referencePreviewItem
```

원칙:

- Review V2의 카드 데이터와 편집 상태를 복제하지 않는다.
- 동일한 캐릭터 상태 객체와 저장 액션을 사용한다.
- 모드 전환 시 편집 중인 태그와 평점이 유실되지 않아야 한다.
- 단일 모드에서 수정한 값이 기존 5카드 화면에도 즉시 반영되어야 한다.

---

## 11. 오류 및 빈 상태

다음 상태를 구분해서 표시한다.

- 레퍼런스 로딩 중
- Wiki Sample 없음, favorite 결과 사용 중
- 레퍼런스 이미지 일부만 존재
- 레퍼런스 이미지 없음
- Danbooru 요청 실패
- 이미지 URL 로딩 실패

레퍼런스 조회가 실패해도 generated image 검토, 태그 수정, 평점 입력, 저장, 재생성, `w` 키는 정상 동작해야 한다.

---

## 12. 완료 조건

다음 조건을 모두 만족하면 구현 완료로 본다.

1. 기존 Review V2 5카드 화면과 단축키가 변경 없이 동작한다.
2. 현재 선택 항목에서 단일 항목 오버레이를 열 수 있다.
3. 화면이 `[A | B]` 구조이며 B는 정보 영역과 5개 레퍼런스 썸네일 영역으로 나뉜다.
4. Wiki Sample을 우선 최대 5장 표시한다.
5. 부족한 슬롯은 favorite 상위 포스트로 채운다.
6. Wiki Sample 썸네일에 명확한 라벨이 표시된다.
7. 레퍼런스 선택 시 확대 또는 원본 포스트 이동이 가능하다.
8. `w` 키의 기존 Wiki 이동 기능이 유지된다.
9. 이전 5개, 현재 1개, 이후 20개 pending 항목을 프리로드한다.
10. 다음/이전 이동 시 페이지 경계를 자동으로 넘는다.
11. `Enter`와 `Ctrl+Enter`가 기존 저장 로직을 재사용한다.
12. 재생성 중인 항목에 기존 회색 오버레이가 표시된다.
13. 레퍼런스 조회 실패가 검토 작업을 막지 않는다.
14. 모드 종료 및 필터·정렬 변경 시 캐시가 올바르게 정리된다.

## 13. 구현 우선순위

### 1차

- 단일 항목 오버레이 UI
- 기존 카드 정보 및 저장 액션 재사용
- pending 항목 이동 및 페이지 경계 이동
- 레퍼런스 5슬롯 UI

### 2차

- Wiki Sample 조회
- favorite 상위 포스트 fallback
- Wiki Sample 라벨
- 썸네일 클릭 시 포스트 열기

### 3차

- 이미지 확대 미리보기
- 이전 5개 / 이후 20개 프리로드
- 캐시 무효화 및 요청 취소 최적화

각 단계에서도 기존 Review V2 기능은 항상 정상 동작해야 한다.
